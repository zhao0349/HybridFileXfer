# 多轨快传 · 桌面 GUI 与可靠传输预览版

本仓库是 [HybridFileXfer](https://github.com/weixiansen574/HybridFileXfer) 的独立维护 fork，保留 USB / Wi-Fi 多通道传输。当前分支为 **4.0.1-preview，协议 401**；手机与电脑必须同时升级，不能混用协议 400 或 3.0 的安装包。`--version` 会显示构建提交号，方便核对源码与产物。

## 开始使用

1. 从本仓库 [Actions](https://github.com/zhao0349/HybridFileXfer/actions) 的同一次成功运行中下载桌面包和 `android-debug-and-reports` APK。桌面 ZIP 自带 Java；Windows 解压后双击 `HybridFileXfer.exe`，不会弹出命令提示符。Linux / macOS 使用对应包，平台和 CPU 架构以构建产物为准。
2. 可以先打开电脑界面，选择 USB / ADB 或网络连接，选择电脑初始目录，点击“等待并连接”。手机未连接或服务尚未启动时，窗口会等待并重试；“停止 / 断开”随时可用。
3. ADB 方式需要已安装 Android platform-tools 并可执行 `adb`，以及手机 USB 调试授权。配对码留空时，电脑自动读取手机已启动会话的配对码和实际端口；手机先启动或电脑先启动均可。勾选“连接时打开手机 App”后，若手机尚未启动服务，电脑会请求启动；在手机上确认配对、IO 模式与所需授权。手填配对码会保留，不被自动替换。网络方式请先在手机启动服务，再将显示的配对码填入已打开的电脑窗口。
4. 在手机双栏文件列表中选择文件，使用明确的“发送到电脑 / 接收到手机”按钮。桌面窗口显示进度、各通道速度、结果与历史。长按可开始选择，选择状态下长按另一项可选择区间；工具栏提供最近目录、存储位置和历史。
5. 断线后可在同一窗口重新连接。任务不会自动重放；重新选择相同源文件和目标目录即可尝试恢复，程序会验证已保存的文件前缀。

[桌面详细用法与 CLI](HybridFileXfer-PC/DESKTOP.md) · [验收与实现范围](docs/implementation-tracker.md) · [校验协议](docs/verification-protocol.md) · [性能测试](docs/transfer-benchmarks.md) · [旧版文档存档](docs/upstream-3.0-readme.md)

桌面默认跟随系统的深浅外观，也可在窗口右上角固定选择浅色或深色。切换主题不会中断传输。诊断日志支持中文显示和复制，通过系统原生保存对话框导出 UTF-8 文本；按钮、复选框等提供清晰的键盘焦点轮廓。窗口与桌面应用图标均沿用原作者的 logo，Windows EXE 内含 16/32/48/256 像素图标。请从新桌面包运行 `HybridFileXfer.exe`；源码目录中的 `start.exe` / `HybridFileXferLauncher.exe` 是旧版入口。手机通道任务以“分块 当前 / 总数”显示位置，整体进度仍显示已传字节。

Windows 资源管理器可能继续缓存原路径的旧文件图标，即使 EXE 内嵌图标和运行后的窗口图标已更新。升级便携版时建议解压到一个新目录；本机已验证新目录正确显示原作者 logo。

## 文件保护与传输选项

默认保留重名文件的两份副本、启用断点恢复，**SHA-256 完整文件校验默认关闭**。CRC32 分块校验始终启用：发送端直接计算当前缓冲区，接收端校验通过后才写入并确认；不匹配时重发该块，不增加正常传输的网络往返，也不为块校验额外读盘。AES-GCM 仍保护传输通道。

时间充足时可在任一端勾选“传输后校验 SHA-256”，无需两端都勾选：所有数据传完后，两端通过有界线程池同时校验多个文件，逐个比较结果；较快的一端等待对端。每轮全部结束后统一重发摘要不匹配的文件，再校验，直到通过或用户停止。文件读取、权限或磁盘等明确错误会记为失败，不无限重传。重传保持最初选定的目标路径，“保留两份”不会每轮生成新的正式副本。

校验开始后可随时点击“停止校验与重试”，连接保持可用，摘要显示通过、失败和未校验的文件数。完整但未校验的文件会保留；若存在同名原文件，另存未校验副本以保护原文件。已知校验失败的文件保留为诊断暂存，不冒充成功文件；停止时未传完的重传副本也不会发布为完整文件。数据传输阶段的“取消传输”仍会关闭当前连接以终止阻塞，之后可重新连接。

文件先写入同目录 `.hfx-*.part`；未开启 SHA 时，完整传输后按冲突策略提交；开启时，比较通过后再提交。失败时原始源文件和已有目标文件不会因清理而被删除；已确认的前缀与 `.meta` 元数据用于恢复。临时文件随实际数据增长，不按源文件的最终大小预分配。可选择覆盖、跳过，或按完整内容校验做增量跳过；增量比较和恢复前缀检查仍需读取相关内容，相同大小不代表相同内容。冲突处理等选项以接收端明确设置为准；SHA-256 则在任一端开启时生效。

单个无法读取、无权限、非法文件名或磁盘写入失败会记录在摘要中，并继续处理后续文件。超长文件名不做有损截断；失败项目有明确原因。若某个数据通道失效，未确认的数据块改由剩余通道处理；控制通道或所有数据通道断开则结束本次任务，保留恢复状态。

默认进度显示已确认字节与当前文件，未知总量不显示虚假百分比。可选预扫描以获得总量，但扫描大量小文件需要额外时间。校验、检查点与加密都有开销，不承诺多通道在所有设备上更快。

## Android 模式与后台运行

正常、Shizuku ROOT、Shizuku ADB，以及新增的 **ROOT（直接 su）** 模式共用文件操作接口。直接 su 功能吸收了 [上游 PR 118](https://github.com/weixiansen574/HybridFileXfer/pull/118) 的设计方向，保留现有模式选择器，补充拒绝、取消、超时和迟到回调清理。存储入口不绕过 Android 权限；外置卡、`Android/data` 和系统目录是否可用取决于所选模式与系统。

传输会话与 Activity 分离，旋转屏幕不重新占用端口；前台通知提供停止入口。长时间锁屏传输时，还需按手机系统设置允许应用后台运行、关闭针对本应用的省电限制，并确保电脑不进入睡眠。前台服务不能保证绕过所有厂商的后台策略。

## 连接、配对与端口

控制和数据通道需要配对认证；数据通道绑定当前会话，并使用 AES-GCM 保护传输。配对码只用于当前会话，不写入历史或偏好设置。只把配对码交给可信设备：配对后的手机文件浏览器可操作电脑当前用户可访问的路径，电脑“初始目录”不是权限隔离边界。Root 模式同样拥有更大的文件访问权限。

ADB 自动配对通过手机已授权的 ADB shell 读取当前会话，不在局域网上广播配对码。该只读接口校验调用方 Linux UID，仅允许 shell / root；普通手机应用无法读取。手机尚未确认启动时不提供配对码，已经连接或停止的会话也不提供。此功能需要同一次构建的桌面和手机新版；手填配对码也不能绕过协议版本检查。

手机服务端口可配置（默认 5740）。ADB 本地端口默认自动分配，避免 Windows 保留端口冲突，仅移除本应用创建的转发规则。ADB Burst Mode 是可选实验项，不会强制重启全局 ADB 服务；其效果需要用目标设备测试。

## 从源码构建

桌面使用 JDK 21 或更新版本和 Python 3.9 或更新版本：

```text
python tools/build_desktop.py --test --package
```

首次构建从 Maven Central 下载并校验固定版本的 FlatLaf 界面库，之后使用本地缓存。结果在 `.build/distributions`，独立 JAR 已包含界面库，保持 Java 8 字节码兼容。旧 Windows / 旧 Java 的运行能力不等于现代打包运行时的支持范围。

Android 使用 JDK 17、Android SDK 34，通过 `HybridFileXfer-Android/gradlew` 运行 `assembleDebug testDebugUnitTest lintDebug`。CI 会编译 JNI 库并生成调试 APK。调试包不是正式签名发布版；若与既有安装签名不同，不能直接覆盖安装，卸载会清除应用设置。

自动测试使用合成数据，覆盖真实 loopback 协议、错误配对、损坏数据、短写、恢复、故障通道、冲突策略与界面状态。它们不替代真实手机、USB 驱动、Root 实现、OEM 后台、外置文件系统和高 DPI 的验收。
